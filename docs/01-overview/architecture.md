## 2.2 核心设计原则

1. **规则引擎做锚点，LLM 做研判**：四维分数全部由规则引擎产出（可解释、可复现），LLM 只做两件事——① 事件类比精排；② 综合四维输入输出最终信号。LLM 不可用时系统仍能给出分数，只是信号降级。
2. **数据获取与分析解耦**：刷新数据（打外网）与跑分析（算分 + LLM）是两个独立动作，避免每次分析都触发 yfinance 请求（也是防风控）。
3. **一切落库可回放**：每次分析的输入、输出、快照全部入库，历史信号序列可回溯、可比对。
4. **降级优先于失败**：任一数据源（尤其 X）不可用时，对应维度计中性分并标注"数据缺失"，主流程不中断。
5. **事件流增量管道**：事件采集是持续高频的独立管道，分析是按需/收盘后的聚合动作，两者解耦；新事件只做增量处理（去重→预过滤→结构化），绝不全量重算。
6. **接缝即契约**：模块间的依赖方向、接口签名、数据流载体与降级行为统一约定在 [10-module-contracts.md](../10-module-contracts.md)，实施时不得绕过。

## 2.3 一次完整分析的数据流

```
[1] 采集（两条独立管道）：
    事件管道（准实时，默认 20min 轮询）：多新闻源增量抓取 → 48h 年龄过滤 → 去重
        → 预过滤 → LLM 结构化抽取（四类事件）→ 价格反应富化 → 新事件入库 + 提醒
    数据管道（低频）：yfinance 行情/财报 + FRED 宏观 + X 帖子入库（X_MODE 双通道）
[2] 事件匹配：当前事件 → 硬检索历史库 top-5 → LLM 精排(相似度/方向/强度) → 每事件 top-3 类比
[3] 四维评分：宏观分(FRED 规则表) / 事件分(类比+X情绪) / 产业分(篮子相对强弱) / 公司分(基本面+技术面)
[4] 综合研判：四维分 + 类比结论 + X 观点摘要 → LLM 一次调用（供应商可配） → 结构化信号列表
[5] 落库：快照 UPSERT、分析日志追加 → Web 面板展示（卡片/技术指标/事件流/类比）
[6] 对话式追问（实施期增补）：报告出来后，用户在"对话"页签多轮追问 LLM
    （上下文=股票池+最新信号+体制层+当前事件含价格反应+事件库，见 analyzer/chat.py）
```
