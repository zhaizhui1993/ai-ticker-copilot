# 05-评分 ｜ 汇总与分档（engine.py）

> 模块：05 评分引擎 ｜ 成分：加权汇总 + 信号分档 + 体制层硬约束 ｜ 实施阶段：P5
> 来源：原方案 §6.1（汇总与分档）+ v1.1 硬约束

## 加权汇总

默认权重 0.25×4（`scoring_weights.yaml` 可调）；`Engine(weights)` 构造时校验权重合计=1.0，非法即抛错拒启。总分 = Σ wᵢ·sᵢ；输出 `EngineOutput`（四维分 + `regime_note` 体制层备注）。

## 信号分档

| 总分 | 含义 | 信号倾向 |
|---|---|---|
| ≥70 | 积极 | 建仓/加仓 |
| 50~70 | 中性偏多 | 观望偏加仓 |
| 30~50 | 中性偏空 | 观望 |
| <30 | 防御 | 减仓/回避 |

**分数是锚点不是结论**：LLM 可偏离分档输出信号，但 prompt 强制要求偏离时在理由开头说明，且必须点名引用支撑偏离的具体输入字段与数值（v1.2，防无出处偏离），保证分数与结论互相印证。

## 体制层分级约束（v1.2 改造，原 v1.1 硬约束）

当 [layered-technicals.md](layered-technicals.md) 体制层判定破位（两个及以上指数收盘 < MA200，或任一指数 < MA200 且 VIX>25，`IndexRegime.regime_broken()`）时：

- 档位上限压至"中性偏多"（积极 → 中性偏多，`regime_note` 标注）；
- 输出**仓位上限系数 `position_cap=0.3`**（正常 1.0）——信号动作上限压至 watch_add（观望偏加仓·小仓）而非一刀切"观望"（v1.1 会系统性错过恐慌底部的建仓窗口：2020-03、2022-10 这类最优买点恰在破位期内）；由 `rule_judge`（无 LLM 时）与综合研判 prompt 规则 5（有 LLM 时）执行，`position_cap` 为系统风险参数，LLM 不得调高；
- 宏观/事件环境仍不进入加权求和、只做门槛；体制层数据获取失败时按"未破位"中性处理并标注。
- **whipsaw 可证伪口径（P1-3）**：`scripts/backtest_signals.py --regime ^SOX` 输出 MA200 破位段的假信号率（≤20 交易日且最深未破 -5% 判为 whipsaw），持续跟踪该比率以验证门槛信噪比。

## 公司面短板门槛（v1.2 新增，P1-1）

公司面分数 < 35（`COMPANY_FLOOR`）时，档位上限压至"中性偏多"（`company_gate_applied` 标注）——防止"公司分 30、其他三维 90 → 总分 75 积极"这类基本面恶化被线性加权平均掉的失真。公司面与体制层约束可叠加。
