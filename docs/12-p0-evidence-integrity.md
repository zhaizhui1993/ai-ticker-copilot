# P0 修订：事件完整性与估值准入（v1.5）

2026-10-10。本文件覆盖 v1.4 中相冲突的事件时间、七天筛选和信号准入规则。

## 事件采集与生命周期

- 原始报道以 URL 与原始标题的 SHA256 为身份，独立持久化正文摘要、来源、发布时间、首次采集时间和处理状态。先存原始报道，提取结果与处理完成状态在同一事务提交；失败保持待处理，重试不依赖 RSS 是否还包含该文章。
- 每篇报道抽取一个主要事件。事件 ID 由原始报道身份确定，不使用日期序号或 LLM 改写后的标题。不同轮询、重启、降级路径都保持同一 ID；数据库只忽略明确的重复键，不吞掉其他写入错误。
- `occurred_date` 只保存有依据的实际发生日，无法确认则为空。单独保留 `published_at` 与 `fetched_at`；分析参考日依次使用发生日、发布时间的美东日期、采集时间的美东日期，并显式标注口径。LLM 以输入文章编号引用来源，不能自造来源链接或时间。
- 当前事件状态为 active / resolved / retracted / merged。active 不受七天窗口截断，按当前事件类型衰减；其他状态不参与评分。数据库读取失败不能冒充“没有事件”，此时禁止新增风险。
- 相同报道自动幂等。不同 URL 的相似报道只允许明确合并，避免错把政策更新合并成旧政策。合并保留原始报道引用和变更日志，源事件变为 merged，目标保持自身状态，合并不重置影响年龄。resolved/retracted 可经人工复核重新启用。
- 状态修改及合并通过 API 显式执行，并要求理由；LLM 无权关闭或合并事件。旧事件 ID 与已知日期兼容；旧流水号丢失的数据不能自动恢复，须重新导入原始报道。
- 发生日未知的事件不得自动沉淀为带精确历史事件日的案例；仅可用已标注的时间代理展示行情背景。

## 估值证据准入

- 区分企业质量、估值依据、价格吸引力。PE/营收增速仍是粗筛，正 PE 本身不能解除估值门槛。
- 本次不实现自动 DCF。每股可在 stocks.yaml 中显式配置经人工复核的 `valuation`：method（dcf/multiples/scenario/sotp）、保守每股价值 conservative_value（USD）、as_of、valid_until、minimum_margin、assumptions、sources、rationale、reviewed。
- 安全边际按 `1 - 最新价 / 保守每股价值` 计算，minimum_margin 必须由使用者显式给出，系统不预设统一比例。只有证据已复核、未过期、估值日期不晚于价格日期、行情时间有效且安全边际达到阈值时，才允许增加风险。阈值和价值来自研究假设，不代表系统证明合理。
- 缺少、未复核、未来日期、过期证据，以及价格不满足条件时，规则和 LLM 最终信号均最高 watch，新增仓位系数为0；已有 reduce 不会被改成买入。不强制亏损公司使用正PE，情景/分部等方法同样可提供证据。
- 输出、提示词、快照及审计日志均记录估值状态和计算结果，避免报告正文看多却在后台静默降级。数值有限且为正，假设、来源和理由不得为空，日期区间须有效。
- 存量股票未配置估值证据时，仍可展示研究分数，但停止输出加仓倾向。这是预期行为。拆股、融资、重大经营变化后，使用者须重新复核原证据。

## 验收

跨批不同新闻不撞ID；同文重试幂等；原始标题与LLM标题不同仍能去重；来源编号无效时安全降级；发布时间跨美东午夜；未知发生日不伪造；30/90天活跃政策仍入分析；生命周期变更可审计；合并不重复计分；失败事务可重试；缺少估值/只有PE/过期/未复核/不足安全边际都不能加仓；亏损公司有有效替代证据可通过估值检查；LLM不能绕过；旧数据可读。

## 使用与升级

启动时 `storage.db.init_schema` 自动幂等增加 `raw_news_articles` 与 `event_changes`，不删除旧表或改写历史发生日。需 MySQL 账号具有建表权限。原文待处理队列每轮最多处理100条，单次LLM最多20篇；失败保留原文，下轮即使RSS已不包含该报道仍可重试。归档的是实际抓到的RSS标题/摘要，不声称保留网站全文。

| 操作 | 接口与参数 |
|---|---|
| 更新状态 | `PATCH /api/events/{event_id}/status`，JSON `{"status":"resolved","reason":"具体复核依据"}`，状态可为 active/resolved/retracted |
| 合并重复报道 | `POST /api/events/{event_id}/merge`，JSON `{"target_event_id":"保留的事件ID","reason":"确认为同一事件的依据"}` |
| 查看变更记录 | `GET /api/events/{event_id}/changes`，返回修改前后数据、理由与UTC时间 |
| 配置估值 | 编辑 `config_files/stocks.yaml`；或 `PUT /api/stocks`，与股票池一起传入 `valuation` |

合并后的源事件不能重新启用；应操作保留的目标事件。目标已关闭时，合并不会自动将其开启。旧客户端保存股票池时，未传入 `valuation` 会保留原证据；显式传入 `null` 才清除。配置示例见 `config_files/stocks.yaml.example`，其中假设数字不是任何股票的推荐估值。

历史快照中的加仓信号若来自旧版本，或当前估值证据检查未通过，总览展示降为观望并提示原因；重新分析后生成当前信号。对话上下文也标记这一限制。

离线回归覆盖业务事务回滚、幂等、生命周期与估值准入；SQLite测试适配器不验证MySQL DDL及并发锁。`tests/test_storage.py` 提供原生MySQL建表重复执行、事务重试与变更审计测试；未配置可用MySQL时自动跳过，不能视为完成真实数据库验收。
