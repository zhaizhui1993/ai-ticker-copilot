# 09-交付 ｜ 风险与应对

> 模块：09 交付与运维 ｜ 成分：风险登记 ｜ 实施阶段：全程
> 来源：原方案 §13

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| 1 | **yfinance 限频/TLS 指纹 429** | 行情拿不到，全链路阻塞 | 固定 yfinance==1.5.2 + curl-cffi 0.15.x；串行+间隔+退避；结果落磁盘缓存；备用 Stooq CSV 切换口（预留未实现） |
| 2 | **X cookie 失效/风控（crawl 通道）** | 情绪分缺失 | 降级为中性 50 分并标注；导出脚本一键重登录；**或切 X_MODE=api 免登录态**；频率克制（每天每博主 1 次） |
| 3 | **twitterapi.io 第三方依赖**（api 通道）：停服/涨价/额度用尽/封 key | X 采集中断 | XApiKeyError 整轮终止并提示查控制台；翻页硬上限 5 页封顶成本（~$0.015/博主/次，5 博主 ≈ $1/月）；可随时切回 X_MODE=crawl |
| 4 | **LLM 供应商/模型名变动或停服** | LLM 调用失败 | 供应商/端点/模型名全在 .env（OpenAI 兼容协议），切换零代码改动；结构化输出默认 function_calling（跨供应商最大公约数）；LLM 挂了系统仍有规则分数可看（对话功能例外，503 明示） |
| 5 | FRED key 未填 | 宏观分缺失 | 启动时明确提示；宏观分降级中性并标注 |
| 6 | 种子事件量化数据不准 | 类比结论失真 | 实施时用 yfinance 按日期实测回填（backfill/mine 工具已备）；用户可在 Web 端修正 |
| 7 | 时区/夏令时混乱 | 快照日期错位 | 一切"日"以美东为准；调度 cron 用 America/New_York；展示层标注 |
| 8 | 手动触发+调度并发 | 重复分析/脏写 | Web 层 threading.Lock + 调度器 max_instances=1；快照 UPSERT 幂等 |
| 9 | 过度依赖 LLM 结论 | 信号不可验证 | 分数与信号分离、偏离必须说明理由、全量输入落库可回放 |
| 10 | 新闻源限频/失效 | 事件管道中断 | 多源冗余、单源失败跳过不影响整体；Google News 主题流免费无 key 作兜底 |
| 11 | 轮询使 LLM 抽取成本上升 | 月 API 费用增加 | 规则预过滤 + 增量去重（只抽取新文章）+ 批量单次调用；预估仍 <¥10/月 |
| 12 | MySQL 服务未启动/故障 | 系统整体不可用 | 启动时健康检查+中文报错指引；Docker 一键拉起；单语句写入天然原子 |
