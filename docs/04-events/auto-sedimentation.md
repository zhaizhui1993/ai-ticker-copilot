# 04-事件库 ｜ 当前事件自动沉淀（v1.1 滚雪球机制）

> 模块：04 历史事件库 ｜ 成分：事件库增长机制 ｜ 对应代码：调度任务（复用 scripts/backfill_events.py 逻辑） ｜ 实施阶段：P9
> 来源：v1.1 新增（原方案 §5.3.1④）

## 机制

事件管道入库的当前事件不只用一次：每条事件在发生后 **T+60 与 T+180 天**由调度器自动复用 backfill 逻辑，回填其实际市场反应（对池内及相关标的的回撤/达底/恢复天数），生成 `source='auto'` 的历史事件草稿；人工核对后正式转入历史事件库参与类比。

```
当前事件入库（03 news-pipeline）
    └─(T+60 / T+180 天，调度器触发)─► 复用 backfill 算法回填实测反应
        └─► source='auto' 草稿（不参与匹配）
            └─► Web 事件库页"待核对"清单
                └─► 人工确认 → 转正式历史事件（参与类比）
```

## 设计要点

- 事件库由此从 10 条种子起步、随使用自动增长，类比能力不再锁死在初始规模；
- **用户不核对则草稿不生效**，保证入库质量（与事实层"人工核对三条清单"同一原则）；
- 动机实证：2026-07 板块回调时，9 条种子无一命中"AI 叙事回调"原型，类比靠"无命中默认偏多"含运气成分——自动沉淀保证原型持续补齐（见 [breach-classification.md](breach-classification.md) 诚实标注）。
