# 投资决策链改动技术方案（v1.6 草案）

日期：2026-10-22。对应 [v1.5 事件完整性与估值准入](12-p0-evidence-integrity.md) 和 [v1.4 研究方案](11-ai-investment-revision.md)。本文定义分批实施的增量改动；只有已标注完成并验收的部分才进入当前契约。

**实施状态**：第一批已开始：A 的完成日线过滤、指数/个股日期核对、盘中观察限制与分析时钟审计，B 的公司/产业事件明确标的过滤，以及 E 的逐次分析记录与下一开盘价前瞻研究已落代码。A 的逐字段 `EvidenceStamp`、完整交易所节假日日历，B 的事件簇，C 的板块/融资观察，D 的估值重审，E 的组合回测与交易成本仍待实施。当前评测仅为信号研究，不是可执行组合回测。

## 1. 目标与边界

目标是让“回调是否企稳、能否增加风险”的结论具有一致的数据时点、明确的事件传导对象、可复核的融资与估值证据，以及可成交的事后评测。保留四维研究排序、人工估值准入、规则最终约束和追加式分析审计；不新增自动下单或未经验证的目标价。

以下是提出本方案时识别的**改动前缺口**。第一批已修复其中一部分；当前实施状态以上方说明为准。

| 改动前缺口 | 涉及代码 | 投资判断风险 |
|---|---|---|
| 日线、指数和财务数据分别获取，未统一可用时点 | `collectors/market.py`、`analyzer/pipeline.py` | 盘中未完成 K 线或不同交易日数据进入同一个“收盘”判断 |
| 费半 ATR 已采集但未参与体制判断；板块宽度未实现 | `domain/scoring.py`、`scoring/engine.py` | 大盘稳定时漏报 AI 板块集中走弱 |
| 所有活跃事件向全池股票传递，未关联股票仍按 0.5 计分 | `analyzer/pipeline.py`、`scoring/event_score.py` | 单家公司消息影响无关股票 |
| 估值有效期内不检查新财报、股数和债务变化 | `domain/valuation.py`、`scoring/valuation.py` | 过时假设继续允许增加风险 |
| 同日快照覆盖，收益从信号日收盘起算 | `storage/repository.py`、`analyzer/evaluation.py` | 收盘后生成的信号被当作能在当日收盘成交 |

实施原则：**无法证明数据可用时只输出研究观察，不放行新增风险**；“未知”不得当作零风险；盘中观察与收盘确认分别展示；所有新规则先记录、回放和校准，再决定是否转为硬门槛。

## 2. 阶段 A：时点与信号身份（最高优先级）

### 2.1 数据契约

新增 `domain/asof.py`，定义跨采集、编排、存储使用的类型：

```text
EvidenceStamp:
  source: str
  observed_for: date | datetime       # 观测期；日线为交易日，财报为报告期
  available_at: datetime | None       # 首次可证明公开/可用的 UTC 时间
  fetched_at: datetime                # 本系统获取时间，UTC
  status: final | partial | unknown

AnalysisClock:
  decision_at: datetime               # 本次研究可用信息截止时间，UTC
  mode: eod | intraday_observe
  price_session: date | None           # 使用的最近已完成美股交易日
  calendar_version: str               # 交易时段/节假日历版本
```

`observed_for`、`available_at` 和 `fetched_at` 分别记录，不能互相代替。行情采集应返回带 `EvidenceStamp` 的封装结果，旧 `DailyBar` 保留供纯计算函数使用；`IndexRegime` 增加其组成数据的交易日及完成状态。FRED 的 `as_of` 是**统计观察期**，还需记录本系统首次获取时间；缺少历史发布时间的宏观或财报数据不能用于历史时点重建。用户手工输入的估值另保留复核时间与依据来源。

### 2.2 编排规则

- `eod`：使用截至 `decision_at` 已完成的同一交易日日线；指数、个股、SPY、固定篮子不齐时，缺失分量标记为未知。允许指数及篮子缺少个别标的时展示研究分，但体制门槛所需指数不齐、目标个股价格缺失或时间不一致时，最终信号最高 `watch`，新增仓位系数为 0。
- `intraday_observe`：只用最近已完成交易日计算 MA、RSI、回撤、估值安全边际；盘中报价独立显示为“参考报价”，不得混入日线或冒充当日收盘确认。若日内事件改变风险，允许提示风险复核，增加风险仍须等有效收盘数据和其余准入条件。在常规交易时段请求 `eod` 也自动降为此模式。
- 禁止 `available_at > decision_at` 的事实进入本次决策；时间未知的历史财报仅能用于当前研究展示，不能作为可回放的历史财务输入。对真实运行仍可记录 `fetched_at` 作为最晚可用上界，绝不倒填成财报发布日期。
- 快照主键仍为 `(snapshot_date, ticker)`，只用于最新展示。每次分析生成稳定 `run_id`，`analysis_runs` 及其逐票信号为评测主数据源；同日重跑不删除早先信号。展示和回放同时保存 `decision_at`、`price_session`、`mode`、完整的各源时间戳及数据完整性状态。

交易日历按美东时区判断，处理节假日、夏令时与提前收市。`date.today()` 不得充当美股交易日；周末/假日允许使用上个完成的交易日，但须显示其日期。与现有 `run_analysis(refresh=False, tickers=None)` 兼容：新增可选 `mode`，旧调用默认 `eod`；在开盘期间请求 `eod` 时选择最近完成交易日。

**改动文件**：`domain/asof.py`（新）、`domain/stock.py`、`domain/scoring.py`、`collectors/market.py`、`collectors/macro.py`、`analyzer/pipeline.py`、`storage/db.py`、`storage/repository.py`、`web/api/analysis.py`、`web/api/dashboard.py`、`scheduler.py`。

**验收**：美东开盘中、收盘后、周末、夏令时及提前收市各有固定时钟用例；跨交易日指数/个股数据不能放行加仓；`partial` 日线不进入 MA200；同日两次分析均可从追加记录找回，展示仍只取最新快照。

## 3. 阶段 B：事件影响对象与去重

新增 `events_lib/exposure.py` 产出 `EventExposure(event_id, ticker, route, evidence, confidence)`；`route` 为 `direct`、`industry`、`market`，`confidence` 为 `verified` 或 `unverified`。作用对象由**当前事件**确定，历史类比只提供机制参照，不能把历史样本关联的股票直接当作本次受影响对象。

| 当前事件 `scope` | 自动作用对象 | 缺失时处理 |
|---|---|---|
| `company` | 原文证实的 `tickers_mentioned` | 无明确标的则不自动计入个股事件分，送人工复核 |
| `industry` | 原文证实的标的，以及经审核的产业链映射 | 映射缺失只记录事件；不得自动扩散到全池 |
| `macro_policy` / `geopolitical` | 全市场共同风险背景；个股额外暴露须有规则或证据 | 仅施加市场级影响，不臆造个股差异 |

事件分改为先按 `EventExposure` 过滤、再做每股类比；移除“未列出标的固定打五折”的默认逻辑。宏观共同风险的影响强度与个股特异风险分开记录，避免与宏观分重复计分。`affected_tickers` 由 LLM 给出时仍须回到原文、人工映射或可核对规则验证；未验证的推断只作说明，不驱动加仓。不同报道指向同一机制时建立**事件簇**，在簇内仅计一次主冲击，保留全部原始文章和生命周期；政策更新若改变条款或生效时间，应作为新事件/版本，不能因题材相近误并。

**改动文件**：`events_lib/exposure.py`（新）、`domain/events.py`、`events_lib/matcher.py`、`scoring/event_score.py`、`analyzer/pipeline.py`、`storage/repository.py`、事件管理 API。

**验收**：A 公司财报只影响 A；产业链事件只影响经证实的相关标的；宏观事件可以到全池，但不重复加权；两篇同一消息不翻倍；政策修订不会被误吞。历史事件无个股关联时，类比结果不产生未经证实的个股冲击。

## 4. 阶段 C：AI 板块与融资风险观察

### 4.1 板块压力

建立版本化的固定 AI 观察篮子，成分及生效日期入配置，不依赖用户自选股票池。每个完成交易日计算：有效覆盖率、站上 MA50 的比例、上涨比例、等权 5/20 日相对 SPY 表现，以及 `^SOX` ATR14 相对自身历史分位。输出 `SectorStress`：`normal`、`elevated`、`severe`、`unknown`，附原始数值、篮子版本和日期。

第一版只在报告和审计中展示；先用跨阶段样本核对其相对现有 MA200/VIX 门槛的增量。达到预先登记的效果与覆盖标准后，再评审是否让 `severe` 限制 `watch_add`。缺少足够篮子数据时为 `unknown`，不能将缺失比例当作 0% 或 100%。不把 ATR 或宽度阈值直接按 2026 年某次回调拟合。

### 4.2 融资压力

在 `Financials` 中分开记录最近季度与年度的经营现金流、资本开支、自由现金流、现金、债务、股数及各字段对应的**报告期和获取时间**。对数据中心/能源基础设施等资金密集型公司，展示净债务、现金消耗、未来融资或稀释风险；同一指标必须同币种、同口径、同财报期，不能把年度现金流与实时债务直接计算为“季度覆盖倍数”。

现有 FRED 高收益债利差只能代表广义信用环境，不能冒充某只公司的债券利差。个券收益率/CDS 只有接入带标的、债券标识、报价时间与来源的可信数据源后才能展示；在此之前，具体融资风险由人工核实的债务到期结构、融资公告和财报证据支持。第一版为风险提示，不给缺失字段自动打“健康”分。若未来要设融资硬门槛，需先证明其对前瞻风险有增量，并说明例外处理。

**改动文件**：`config_files/` 篮子配置（新）、`domain/scoring.py`、`domain/stock.py`、`collectors/market.py`、`scoring/industry_score.py`、`scoring/company_score.py`、`analyzer/pipeline.py`、Web 体制层展示。

**验收**：只跌半导体、大盘及 VIX 平稳的样例能标出板块压力；单只篮子成分缺数据时覆盖率正确；融资指标不混用年/季口径；未接入个券信用数据时不显示伪造的利差。

## 5. 阶段 D：估值依据的持续有效性

扩展 `ValuationEvidence`，增加 `reviewed_at`、`basis_filing_period`、`basis_shares`、`basis_net_debt`、`invalidation_triggers` 和 `evidence_version`。旧 YAML 字段仍可读取，但新增字段缺失时状态为 `needs_review`，不自动继承旧版 `reviewed=true` 的放行资格。`ValuationAssessment` 增加 `needs_review` 状态及触发证据。

每次分析先比较估值依据与**可证明已公开**的最新财报、增发/拆股、债务或重大经营事件。触发后只把准入状态降为待复核，并在审计中记录触发原因；不能由 LLM 自动重写 `conservative_value`。人工确认新版本后才恢复准入。相同企业的不同估值方法可并存为研究材料，但仅允许一份明确指定且通过复核的证据作为当前准入依据。维持 v1.5 的安全边际计算与最终约束顺序。

迁移时不改写历史估值或历史信号；新版本在首次启动后对旧估值标记 `needs_review`，给出需补录字段。拆股导致的每股价值与价格口径须在人工复核前保持禁止新增风险。

**改动文件**：`domain/valuation.py`、`scoring/valuation.py`、`config/loader.py`、`config_files/stocks.yaml.example`、`analyzer/constraints.py`、股票池 API、Web 估值状态。

**验收**：新财报、增发、拆股、债务显著变化触发待复核；不相关的新报道不误触发；未确定公布时间的资料不能倒灌历史决策；LLM 仍不能解除限制；旧配置可读但不会静默放行。

## 6. 阶段 E：可成交的信号评测

评测输入改为 `analysis_runs` 中的逐次信号与 `AnalysisClock`，日快照仅用于展示。每个信号固定以下字段：生成时间、数据截止时间、所用价格交易日、动作、当时股票池、估值/体制/事件准入状态、规则与模型版本。初版执行价设为**信号生成后的下一常规交易时段开盘价**，另报下一收盘价敏感性分析；不得使用信号生成前的收盘价。行情需使用同一复权口径，费用和滑点作为明确参数展示。

评测区分：① 单次信号的 5/20/60 个交易日前瞻研究；② 真正可执行的组合模拟。前者按 `run_id` 保留同日各次信号，报告重叠样本及按事件/日期聚类的有效样本量；后者只有录入持仓数量、现金、目标权重和交易规则后才能启动，不能把 `position_cap` 当作真实组合权重。基准同时提供 SPY、相应行业 ETF 与**当时可知的**股票池等权组合，明确各自回答的问题。按时间滚动留出样本外验证，参数确定后冻结版本，避免同一回调同时用于拟合和宣称验证。

财务资料无法恢复当时公开版本的旧信号只能评测价格后验表现，不纳入“完整策略历史回测”；已有 `snapshots` 不补造 `decision_at`。月报同时显示可评估条数、排除条数及原因、成交假设、信号覆盖率、超额收益、最大不利变动和置信区间。样本不足时不以单一胜率决定阈值。

**改动文件**：`storage/db.py`、`storage/repository.py`、`analyzer/evaluation.py`、`scripts/backtest_signals.py`、`scheduler.py`、评测文档。

**验收**：16:30 美东产生的信号只能按下一交易时段成交；同日两次信号不丢失；周末/假日顺延；停牌或无开盘价标记不可成交；缺少当时财务版本的旧样本不进入完整策略回测；结果可由存档输入复算。

## 7. 实施顺序、迁移与发布闸门

| 批次 | 依赖 | 可交付结果 | 发布闸门 |
|---|---|---|---|
| A 时点与信号身份 | 无 | 带时间戳的分析、追加式逐次信号 | 时点边界测试与旧数据只读兼容通过 |
| B 事件作用对象 | A | 可解释的每股事件暴露与机制去重 | 无关公司事件不影响别股，现有事件生命周期测试通过 |
| C 板块/融资观察 | A、B | AI 集中压力和融资证据卡片 | 缺失不误判，历史对照仅作探索性报告 |
| D 估值持续有效 | A、C 的财务口径 | 新旧估值的待复核迁移 | 旧证据不会静默放行，人工复核路径可用 |
| E 可成交评测 | A，建议在 B–D 稳定后定版 | 新版月报与样本外验证 | 交易时点、复权、排除样本可复算 |

迁移采用新增字段/表、读取兼容和版本化解释，不删除原表或重写旧 `analysis_runs`；快照继续 UPSERT 供页面展示。新规则以 `decision_version=1.6` 标识，新旧信号分开评测。先在 mock 与回放模式验证，再在真实源旁路记录一段时间，人工检查错误与缺失率；任何新增硬约束只在对应验收通过后开启。MySQL 迁移必须在真实实例做重复执行、并发重跑和回滚验证；SQLite/Mock 通过不能代替该项。

## 8. 最小验证集

- 时点：盘中未完成日线、盘后信号、节假日、夏令时、指数与个股错日、财报发布时间未知。
- 事件：公司/产业/宏观三种范围、同一消息多源报道、政策修订、无明确标的、LLM 输出未经证实的对象。
- 风险：AI 篮子集中下跌但 VIX 平稳、篮子覆盖不足、净债务或现金流缺口、个券报价缺失。
- 估值：旧 YAML、过期证据、拆股、增发、新财报、人工复核恢复、LLM 尝试绕过。
- 评测：同日两次分析、下一交易日开盘成交、停牌、复权、股票池成分变化、重叠观察窗。

验收命令建议使用 `uv run pytest` 加真实 MySQL 集成测试，并输出一份逐项标明“自动测试 / 人工复核 / 外部数据待接入”的验收记录。本文不以一次历史回调的拟合表现作为上线依据。
